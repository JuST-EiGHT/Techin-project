# Ozon Analytics — описание проекта

Этот документ объясняет проект целиком: зачем он нужен, что в итоге получится,
как устроен и почему приняты те или иные решения. Читать первым — до кода и до
остальной документации.

---

## 1. Откуда взялся проект

### Бизнес

Владелец продаёт оригинальные подшипники (бренд NACHI, ~78 артикулов) на Ozon
по схеме **FBO** — товар лежит на складах Ozon, Ozon сам доставляет покупателю.

- **Поставщик** — ТЕХИНТЕЛС, компания-импортёр, которая продаёт подшипники
  заводам. Она пригласила владельца заниматься продажами на маркетплейсах.
- **Юрлицо** — отдельное, оформлено на владельца. Позиционирование в карточках:
  собственный магазин + «официальный партнёр ТЕХИНТЕЛС».
- **Роли:** владелец отвечает за всё внешнее (склад, логистика, внешнее
  продвижение, а теперь и этот сервис); партнёр — за работу внутри маркетплейса
  (карточки, акции, продвижение на площадке).

### Проблема

Ozon не показывает продавцу простой ответ на вопрос «сколько я заработал».
Чтобы его получить, владелец каждую неделю делал вручную:

1. выгружал из кабинета «Отчёт по начислениям»;
2. фильтровал строки с типом «Выручка»;
3. через ВПР подтягивал себестоимость каждого проданного подшипника;
4. суммировал себестоимость, умножал на 1,22 (НДС) — это долг поставщику;
5. из суммы, которая придёт от Ozon, вычитал долг, брал 20% — налог;
6. считал, что останется себе.

Раз в месяц то же самое — по «Отчёту о реализации», с другой структурой файла.

Плюс постоянные вопросы, на которые нет быстрого ответа: какие товары работают
в минус, выгодно ли входить в акцию, какие остатки вывезти со складов, чтобы
не платить за хранение и страхование, куда и сколько везти.

### Что уже сделано до этого репозитория

В отдельном чате был собран **HTML-калькулятор** (`reference/ozon_calculator.html`):
пользователь перетаскивает XLSX из Ozon, калькулятор сам определяет тип отчёта,
находит нужные строки, подтягивает себестоимость и показывает P&L. Он работает
и используется. В процессе выяснилось много неочевидного про формат отчётов
Ozon — всё это зафиксировано в `docs/BUSINESS_LOGIC.md`.

Калькулятор упёрся в потолок: нет истории отчётов, нельзя вернуться и поправить
прошлую неделю, нет данных о ценах, остатках и акциях — только то, что есть
в одном файле. Отсюда решение строить полноценный сервис.

## 2. Что получится в итоге

**Веб-сервис по подписке** — как MPStats, Маяк или SelSup. Пользователь заходит
на сайт, регистрируется, подключает API-ключи своего магазина Ozon и получает
кабинет с аналитикой. Ничего не нужно устанавливать.

Сначала сервис делается для собственного магазина. Когда он стабильно работает —
открывается другим продавцам с тарифами и оплатой.

### Разделы кабинета

| Раздел | Что даёт продавцу |
|---|---|
| **Главная** | Дашборд: остаток на счетах, деньги у Ozon к выплате, продажи, прибыль и маржа, графики выручки и денег, прогноз остатка и ближайшие платежи |
| **Деньги** | Банковские счета и операции (автоматически из банков по API или выпиской), статьи ДДС с автоправилами, ДДС, сверка выплат Ozon с поступлениями на счёт, платёжный календарь и прогноз кассовых разрывов |
| **Финансы** | P&L за любой период: сколько продал, сколько пришло от Ozon, долг поставщику, налог, остаток, маржа. Разбивка начислений по типам. Ручная правка «сколько реально пришло на счёт» |
| **Отчёты** | История загруженных XLSX — отдельно недельные и месячные. Можно открыть любой и поправить цифры |
| **Товары** | Таблица всех товаров: цена, себестоимость, комиссия, маржа, остаток, дни запаса. Быстрые фильтры «в минус», «мало остатков», «нет себестоимости» |
| **Цены** | Минимальная и целевая цена для каждого товара. Изменение цен в Ozon прямо из сервиса — с предпросмотром, подтверждением и возможностью отката |
| **Акции** | Все акции Ozon, маржа каждого товара в акции, товары, которые Ozon добавил без спроса. Вход и выход из акции |
| **Склады** | Остатки по каждому складу, что заканчивается, что лежит мёртвым грузом и что стоит вывезти |
| **Поставки** | Рекомендации «что, куда и сколько отправить», выгрузка в Excel для логиста |
| **Уведомления** | Аномалии: упали продажи, изменилась цена или комиссия, кончается остаток, товар в акции в минус. Дублируются в Telegram |
| **Себестоимость** | Справочник цен закупки с историей изменений и импортом из CSV |
| **Настройки** | Меню аккаунта справа вверху: аккаунт, API-ключи Ozon, банки, основные настройки (тёмная / светлая тема, параметры расчётов по умолчанию), уведомления Telegram, тариф |

### Чего сервис не делает

- Не анализирует конкурентов и ниши (это MPStats/SellerStats — другой класс сервисов).
- Не меняет цены сам по себе без явно включённых правил и жёстких ограничений.
- Не заменяет бухгалтерию — это управленческий учёт для продавца.
- Не отправляет платежи из банка — только читает выписки (docs/MONEY.md).

## 3. Откуда берутся данные

Три источника, и у каждого своя роль.

**XLSX-отчёты из кабинета Ozon** — главный источник для денег. Отчёт по
начислениям и отчёт о реализации совпадают с тем, что Ozon реально выплачивает.
Пользователь загружает их на сайт.

**Ozon Seller API** — главный источник для всего остального: товары, цены,
комиссии, остатки по складам, акции, отправления. Синхронизируется в фоне
автоматически. Финансовые данные из API тоже есть, но Ozon официально предупреждает,
что они могут расходиться с кабинетом — поэтому для P&L сервис предпочитает XLSX,
а API-данные показывает с пометкой.

**Банки** — деньги на расчётных счетах: операции и остатки по API банка (автообновление)
или выпиской в формате 1С для любого банка. Отсюда ДДС, сверка выплат Ozon и платёжный
календарь (docs/MONEY.md).

**Чего нет ни там, ни там:** себестоимость (ведётся в сервисе вручную или
импортом), история цен (сервис копит снимки сам), детальные расходы на рекламу
(это отдельный Ozon Performance API, подключается позже).

## 4. Как устроено

```
                   Браузер пользователя
                          │
                        Nginx
                   ┌──────┴──────┐
              Next.js         FastAPI ───── PostgreSQL
            (интерфейс)      (бэкенд)          │
                                │           Redis
                                │              │
                           Celery-воркеры ─────┘
                           (фоновые задачи)
                                │
                         Ozon Seller API
```

- **Next.js** — интерфейс кабинета и лендинг.
- **FastAPI** — вся логика и API для интерфейса.
- **PostgreSQL** — пользователи, товары, цены, остатки, начисления, отчёты, история.
- **Redis** — очередь задач, кэш, счётчик лимитов Ozon API, отозванные токены.
- **Celery** — фоновая синхронизация с Ozon (товары раз в час, остатки раз в
  30 минут, финансы раз в 6 часов, акции раз в 3 часа), поиск аномалий, уведомления.

### Путь данных внутри бэкенда

```
XLSX-файл ─┐                         ┌─ Ozon API
           ▼                         ▼
     ReportDetector           Синхронизация (Celery)
     (какой это отчёт?)              │
           ▼                         ▼
  AccrualReportParser /         Таблицы в БД
  RealizationReportParser            │
           └──────────┬──────────────┘
                      ▼
            NormalizedReportData      ← единый формат, не зависит от источника
                      ▼
                  PnLEngine           ← чистые формулы, без БД и HTTP
                      ▼
               API → интерфейс
```

Ключевой принцип: **разные форматы входных данных сводятся к одной структуре,
а расчёт — один на всех.** Никаких «калькулятор для недельных» и «калькулятор
для месячных» по отдельности.

### Обратный путь — изменение данных в Ozon

```
Пользователь задаёт новую цену
        ▼
Предпросмотр (dry-run): было → станет, маржа, предупреждения
        ▼
Проверки безопасности (не больше 20%, не ниже себестоимости, пауза, лимиты)
        ▼
Подтверждение пользователем
        ▼
Запись в аудит-лог → запрос в Ozon → запись ответа → снимок новой цены
```

## 5. Ключевые решения и почему

| Решение | Почему |
|---|---|
| Сайт, а не приложение | Работает на любом устройстве, не нужно ставить, так устроены все конкуренты |
| Python + FastAPI | Лучшие библиотеки для Excel и расчётов, быстрая разработка |
| XLSX — главный источник для P&L | Совпадает с реальными выплатами; данные API Ozon официально могут расходиться |
| Семантический парсинг отчётов | Ozon меняет формат без предупреждения; поиск по номеру строки ломался постоянно |
| Неизвестная себестоимость ≠ 0 | Ноль тихо завышает прибыль; лучше явно показать, чего не хватает |
| Проценты доходов и расходов — по 100% в каждой группе | Иначе сумма процентов выходит за 200% и сбивает с толку |
| Изменение цен только через dry-run и аудит | Одна ошибка в данных Ozon может испортить цены сотен товаров |
| Автоматика цен — последней | Только после нескольких месяцев ручного режима без инцидентов |
| Сервер в России | Скорость для пользователей и 152-ФЗ о персональных данных |

## 6. Этапы

Полная таблица — `docs/ROADMAP.md`. Коротко:

| Фаза | Результат для продавца |
|---|---|
| 0. Фундамент | Можно зарегистрироваться и войти, подключить ключи Ozon |
| 1. Ozon API | В сервисе появляются товары, цены, остатки, начисления, акции |
| 2. XLSX | Загрузка отчётов на сайт, история, справочник себестоимости |
| 3. Финансы | Страница финансов (P&L, как HTML-калькулятор, но лучше), прибыль по товарам; деньги: банки по API, ДДС, платёжный календарь, главный дашборд |
| 4. Товары и акции | Маржа по каждому товару, минимальная цена, выгодность акций |
| 5. Склады | Что заканчивается, что вывезти, что и куда везти |
| 6. Цены | Безопасное изменение цен в Ozon из сервиса, история и откат |
| 7. Аномалии | Сервис сам сообщает о проблемах, в том числе в Telegram |
| 8. Запуск | Тарифы, оплата, лендинг, сервер — сервис открыт другим продавцам |
| 9. Автоматизация | Правила: «если маржа ниже X — поднять цену», автоуправление акциями |

**Порядок:** после 2.2 — `2.3 → 3.1 → 3.2 → 3.3` (сайт заменяет HTML-калькулятор и даёт
историю отчётов с правкой «сколько пришло» и налога), затем `3.4 → 3.5` и деньги
`3.6 → 3.11` (банки, ДДС, платёжный календарь, главный дашборд), потом фазы 4–9.

### Тарифы (план)

| Тариф | Цена | Что входит |
|---|---|---|
| Бесплатный | 0 ₽ | P&L по загруженным XLSX, 1 магазин |
| Базовый | 1 490 ₽/мес | + синхронизация с Ozon API, аналитика товаров, акции |
| Профессиональный | 3 990 ₽/мес | + изменение цен, склады, поставки, аномалии |
| Автоматизация | 7 990 ₽/мес | + правила автоизменения цен и акций |

Ориентировочная стоимость инфраструктуры на старте — 3–4 тыс. ₽ в месяц
(VPS 4 CPU / 8 GB в Timeweb Cloud или Selectel + хранилище + домен).

## 7. Риски

| Риск | Что с ним делаем |
|---|---|
| Ozon отключает или меняет методы API (так уже было 6 июля 2026) | Храним сырые ответы, сверяемся с документацией перед каждой интеграцией, XLSX как запасной путь |
| Данные API расходятся с кабинетом | Для P&L приоритет XLSX, источник всегда показан пользователю |
| Ошибочное массовое изменение цен | Жёсткие лимиты, dry-run, подтверждение, аудит, откат, проверка аномальных данных |
| Потеря истории: прошлые цены, остатки и акции Ozon не отдаёт | Копим снимки сами с первого дня работы сервера и ничего не удаляем, храним исходные файлы отчётов, резервные копии глубиной в год (`docs/DATA_HISTORY.md`) |
| Банки дают API по-разному, крупным нужен договор с сервисом | Общий коннектор `BankProvider`; сначала банки с токеном от клиента, партнёрства — к запуску; для любого банка — выписка файлом |
| Утечка API-ключей продавцов | Шифрование, ключи не логируются и не возвращаются, права ключей — минимально нужные |
| Рынок плотный (SelSup, TrueStats, ПланФакт, Управляйка, КУБ24 и др.) | Сначала решаем свои задачи; отличие — специфика запчастей и связка «склад + цены + P&L» |
| Проект отвлекает от основного бизнеса | Короткий путь сначала даёт пользу самому магазину, монетизация — только когда работает |
