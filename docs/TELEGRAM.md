# Telegram-бот уведомлений (шаг 7.3)

Сервис раз в час ищет аномалии (шаг 7.1); новые — в колокольчике на сайте (7.2) и, если пользователь подключил
Telegram, — в его чате с ботом. Бот один на весь сервис (его создаёт владелец сервиса), каждый пользователь привязывает к
нему свой чат кодом с сайта.

## Как включить

1. В Telegram открыть [@BotFather](https://t.me/BotFather) → `/newbot` → имя («Ozon Analytics») и имя пользователя бота
   (`…_bot`). BotFather пришлёт токен вида `123456789:AA…`.
2. В `.env` на сервере (не в репозитории — правило 11):
   ```
   TELEGRAM_BOT_TOKEN=123456789:AA…
   TELEGRAM_BOT_USERNAME=имя_бота      # без @ — для кнопки «Открыть бота»
   SITE_URL=https://адрес-сайта        # ссылки в сообщениях
   ```
3. `docker compose up -d bot worker beat` (на сервере — `./scripts/compose.sh up -d`, `README-DEPLOY.md`, раздел 6) —
   сервис `bot` отвечает на команды, `worker` отправляет уведомления, `beat` раз в 5 минут досылает отложенные (тихие часы,
   сбой сети).

Без `TELEGRAM_BOT_TOKEN` всё работает как раньше: уведомления только на сайте, сервис `bot` пишет в журнал «бот не
запущен» и выходит без ошибки, на странице настроек — «Telegram-бот на сервере ещё не подключён».

`TELEGRAM_API_URL` — свой [сервер Bot API](https://github.com/tdlib/telegram-bot-api) вида `https://host/bot`; обычно не
нужен. Им же сквозная проверка шага 7.3 направляла бота и сайт на фейковый Telegram.

## Как пользователь подключает

Меню аккаунта → «Интеграции» → «Telegram» → «Подключить Telegram» (до шага 10.1 — в «Уведомлениях»; что присылать и
тихие часы остались там): сайт показывает код из 6 цифр (действует 10 минут, один раз) и
кнопку «Открыть бота» — ссылка `https://t.me/<бот>?start=<код>` открывает бота, Telegram сам отправляет `/start <код>`.
Бот привязывает этот чат к аккаунту, страница видит это сама (опрос раз в 3 с). Только личный чат: в группе
уведомления увидели бы другие. Неверный код — не больше 5 попыток за 10 минут на чат.

Команды бота: `/start <код>` — подключить; `/status` — что присылаем, тихие часы, сколько активных уведомлений;
`/test` — тестовое сообщение; `/stop` — отключить (на сайте уведомления остаются); `/help`.

## Что и когда приходит

- **Что** — четыре группы, каждая аномалия ровно в одной: «Красные» и «Жёлтые» (товары: продажи, цены, маржа, остатки,
  убыток в акции), «Автоакции» (Ozon сам добавил товар в акцию), «Деньги» (выплаты Ozon, сверка с банком, кассовый разрыв,
  операции без статьи). По умолчанию жёлтые выключены — их больше, на сайте они видны всегда.
- **Когда** — сразу после проверки (раз в час); одна новая — подробное сообщение со ссылкой на сайт, несколько — одно
  сообщение-сводка (красные первыми, до 10, остальное — «и ещё N — на сайте»).
- **Тихие часы** — в часовом поясе пользователя (пояса России, без летнего времени): сообщения копятся и уходят одним после
  конца тихих часов. Изменили тихие часы — ожидающие перепланируются. Тестовое сообщение приходит всегда.
- **Несколько магазинов** (шаг 8.4b): Telegram — один на аккаунт. Сообщения всех магазинов приходят в этот чат одним
  потоком (сводка — общая), у каждого уведомления — название магазина, а ссылка открывает сайт сразу в нём (`?store=`).
  /status показывает уведомления по каждому магазину.
- **Карта сервиса (шаги 10.5, 10.25):** новые категории — ошибки синхронизации и загрузки отчётов, неполные данные
  (раздел «Данные»), изменения цен; позже — результаты и ошибки автоматизации (9.x). Ссылки ведут на новые страницы
  (статистика товара, поставка, выплата, правило). Каналы — сайт, Telegram, e-mail (после почты 8.3a).
- **Не дублируем**: одна аномалия — одно сообщение (уникальный индекс журнала). Перед отправкой ещё раз: аномалия не
  закрылась, не отмечена «Ок» на сайте, группа не выключена — иначе не шлём.
- **Сбои**: пользователь остановил бота — сообщение не уйдёт, на сайте «Бот не может вам написать»; лимит Telegram — повтор
  через указанное время; Telegram недоступен — повтор через 5 минут, после 5 попыток — не отправится. Журнал —
  `notification_log`.

## Токен

Только в `.env`. В API не возвращается (там лишь имя бота), в журнал не попадает: токен стоит в адресе каждого запроса к
Telegram, а httpx пишет адреса в журнал на уровне INFO, python-telegram-bot — на DEBUG, и текст его ошибки «токен не
принят» содержит сам токен. Поэтому `integrations/telegram.protect_logs` вырезает токен из любой записи журнала и
трассировки, `redact` — из текстов ошибок, которые мы храним. Проверено тестами (`test_token_never_in_logs_errors_or_api`)
и на живых процессах API и бота.

## Версия библиотеки

python-telegram-bot 22.8 (12.06.2026, Bot API 10.0) — сверено по PyPI и сигнатурам установленной библиотеки:
`Application.builder().token(…).base_url(…).post_init(…).build()`, `run_polling(allowed_updates=[…])`,
`CommandHandler`, `Bot.send_message(chat_id, text, parse_mode, link_preview_options)`, ошибки `Forbidden`, `BadRequest`,
`RetryAfter` (`retry_after` — пока секунды, позже `timedelta`: учитываем оба), `InvalidToken`, `TimedOut`, `NetworkError`.
Требует httpx < 0.29 — у нас 0.27.2.
