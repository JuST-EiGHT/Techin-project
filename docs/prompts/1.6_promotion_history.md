Шаг 1.6 — история участия в акциях (принципы — docs/DATA_HISTORY.md).

Сейчас (шаг 1.5) при выходе товара из акции строка promotion_products удаляется — потом не узнать,
в каких акциях был товар и по какой цене.

1. Миграция: у участия — дата входа (first_seen_at) и дата выхода (left_at, nullable).
   Повторный вход в ту же акцию — новая строка. Изменение акционной цены или заявленного
   количества — сохранять прежнее значение (снимок при изменении, как цены в 1.2).
2. Синхронизация: товар пропал из участников — left_at = время синхронизации, строка остаётся.
   Кандидатов (ещё не участвуют) можно по-прежнему заменять целиком — их история не нужна.
   Закончившиеся акции не удалять.
3. Существующие API показывают только текущих участников (left_at is null) — поведение не меняется.
4. GET /api/v1/promotions/history (product_id, date_from, date_to): в каких акциях был товар,
   когда вошёл и вышел, по какой цене, добавлен ли автоматически.
5. Тесты: выход и повторный вход, смена акционной цены, история по товару за период.
