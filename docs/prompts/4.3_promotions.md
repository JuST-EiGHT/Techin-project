Шаг 4.3 — управление акциями. Это первое ИЗМЕНЕНИЕ данных в Ozon — правила безопасности
из docs/BUSINESS_LOGIC.md §8 обязательны (если шаг 6.1 ещё не сделан — сначала сделай
минимальный audit_log).

0. Сначала — история участия (docs/DATA_HISTORY.md). Сейчас (шаг 1.5) при выходе товара из акции
   строка promotion_products удаляется — потом не узнать, в каких акциях был товар и по какой цене.
   - Миграция: у участия дата входа (first_seen_at) и выхода (left_at, nullable); повторный вход —
     новая строка; изменение акционной цены или количества — снимок прежнего значения (как цены в 1.2).
   - Синхронизация: товар пропал из участников — left_at = время синхронизации, строка остаётся.
     Кандидатов можно по-прежнему заменять целиком. Закончившиеся акции не удалять.
   - Текущие эндпоинты показывают только участников с left_at is null.
   - GET /api/v1/promotions/history (product_id, date_from, date_to): в каких акциях был товар,
     когда вошёл и вышел, по какой цене, добавлен ли автоматически. Тесты: выход и повторный вход,
     смена акционной цены, история по товару за период.
1. GET /api/v1/promotions (средняя маржа, сколько товаров выгодны), GET /{id}.
2. POST /{id}/products/{product_id}/join и /leave — через /v1/actions/products/activate|deactivate,
   только с confirm=true, каждое действие в audit_log.
3. Список акций карточками, бейдж «СРОЧНО», если freeze_date завтра.
4. Страница акции: вкладки «Выгодные» (>10%), «Невыгодные» (0–10%), «Убыточные» (<0%);
   вход/выход с модальным подтверждением.
5. Баннер «У вас N товаров, добавленных в акции автоматически».

> По документации Ozon (docs/ozon/): вход в акцию — `/v1/actions/products/update`, выход —
> `/v2/actions/products/deactivate` (v1 activate/deactivate отключаются 13.10.2026).
