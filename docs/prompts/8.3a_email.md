Шаг 8.3a — почта: подтверждение адреса, сброс пароля, приглашения. Делается после лендинга (8.3) — до того, как
регистрация откроется для других продавцов; модуль писем потом использует оплата (8.2).

1. Отправка писем — services/mail: SMTP российского сервиса (Яндекс 360 для бизнеса, Unisender Go или аналог —
   выбор с владельцем), очередь Celery с повторами, журнал отправок без содержимого писем; настройки — в .env,
   SPF / DKIM / DMARC — в README-DEPLOY.md.
2. Письма — по-русски, в стиле сервиса, текст + HTML: подтверждение почты при регистрации, «Забыли пароль?» (ссылка
   на 1 час, одноразовая, после смены пароля — выход на всех устройствах), приглашение (ссылка с кодом из шага 8.4),
   ответ на заявку с лендинга. Не отправлять токены и ключи в письмах, не раскрывать, есть ли такой адрес.
3. Страницы /forgot-password, /reset-password, /verify-email; лимиты на повторную отправку.

После шага владелец решает, открыть ли регистрацию (REGISTRATION_MODE=open) для ранних пользователей.
Тесты: ссылки одноразовые и с истекающим сроком, неизвестный адрес — тот же ответ, лимиты, письма уходят через очередь
(отправка в тестах — заглушка).
