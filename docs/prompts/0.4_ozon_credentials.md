Шаг 0.4 — хранение API-ключей Ozon.

Бэкенд:
1. Миграция api_credentials: id, user_id (FK users), label, client_id, api_key_encrypted,
   is_active, expires_at (по умолчанию +6 месяцев), last_used_at, created_at.
2. services/encryption.py — Fernet, ключ из ENCRYPTION_KEY; encrypt/decrypt.
   Если ключ не задан или невалиден — понятная ошибка при старте, а не в момент запроса.
3. services/ozon_auth.py — verify_ozon_credentials(client_id, api_key): тестовый запрос
   POST /v3/product/list с limit=1; вернуть ok/ошибку на русском (неверные ключи, нет прав, Ozon недоступен).
4. Роутер /api/v1/credentials: POST (добавить, перед сохранением проверить), GET (список без ключа,
   client_id замаскирован), DELETE /{id}, POST /{id}/verify. Пользователь видит только свои ключи (404 на чужие).
5. Api-Key никогда не возвращается и не попадает в логи — добавь тест, который это проверяет.
   Запросы к Ozon в тестах мокать (respx или monkeypatch httpx).

Фронтенд: /dashboard/settings/api-keys — список, форма добавления, кнопка «Проверить»,
удаление с подтверждением, предупреждение если до истечения < 30 дней.

> Уточнено по документации Ozon (docs/ozon/): ключ живёт 3 месяца, точный срок — `POST /v1/roles` → `expires_at`.
