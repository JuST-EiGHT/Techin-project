Шаг 3.6 — банковские счета и операции, загрузка выписки файлом. План раздела — docs/MONEY.md.

Это фундамент раздела «Деньги» и запасной путь для любого банка: прямые интеграции по API —
шаг 3.7, они пишут в те же таблицы.

1. Миграции bank_accounts (банк, БИК, номер счёта, валюта, источник api | file) и
   bank_transactions (дата, сумма + приход / − расход, контрагент, ИНН, счёт контрагента,
   назначение, номер документа, банковский id операции, источник, raw_json) и
   bank_balances (остаток на дату). Правило 12: операции не удаляются и не
   перезаписываются; повторная загрузка того же периода не создаёт дублей.
2. integrations/bank/statement_1c.py — разбор файла обмена с 1С (1CClientBankExchange,
   кодировки windows-1251 и utf-8, версии 1.02/1.03): секции РасчСчет и Документ, приход
   или расход — по тому, наш ли счёт у плательщика. Понятные ошибки на русском.
   Тестовые файлы — синтетические, без реальных выписок (правило 11).
3. POST /api/v1/bank/statements/upload (предпросмотр: счёт, период, сколько новых операций и
   дублей), GET /api/v1/bank/accounts, GET /api/v1/bank/transactions (счёт, период, приход /
   расход, поиск, пагинация).
4. Поступления от маркетплейсов помечать по ИНН плательщика из справочника (Ozon — ООО
   «Интернет Решения», ИНН 7704217370). Справочник — данные, не код.
5. Страница /dashboard/money: счета с остатками, таблица операций, загрузка выписки
   (инструкция «где взять файл 1С в интернет-банке»).

Тесты: разбор файла, кодировки, дубли при повторной загрузке, приход/расход, чужие счета.
