Шаг 3.7 — банки по API с автообновлением. План и сведения о банках — docs/MONEY.md §4.

1. integrations/bank/base.py — BankProvider: check_access, list_accounts, transactions(счёт,
   период, курсор), balances. Ошибки банка → понятные русские тексты (как OzonAPIError).
2. Первые провайдеры — банки, где токен выдаёт сам клиент: Т-Банк (T-API, выписка
   bank-statement; лимит 10 запросов/с), Точка (публичный API выписок), Модульбанк — если
   API доступен клиенту. Перед реализацией сверить эндпоинты, авторизацию и лимиты с
   официальной документацией банка; если её нельзя открыть из облачной среды — попросить
   владельца выгрузить её в docs/banks/ (как docs/ozon/).
3. bank_connections: провайдер, токен только Fernet-шифротекст (правило 7 — никогда не
   логировать и не возвращать), статус, срок, last_sync_at. Права — только чтение выписок.
4. Синхронизация через общий runner (services/sync/runner.JOBS, kind="bank"): при
   подключении — история насколько отдаёт банк, дальше — каждые 30–60 минут и кнопка
   «Обновить». Дубли с операциями из файла (шаг 3.6) не создавать.
5. API: POST /api/v1/bank/connections (проверить доступ и сохранить), GET, DELETE,
   POST /{id}/verify; статус синхронизации банка — в GET /api/v1/sync/status.
6. /dashboard/settings/banks (пункт «Банки» в меню аккаунта) — подключение банка с пошаговой инструкцией «где взять токен»
   для каждого банка; статус и время последнего обновления.

Тесты: на фейковых ответах банков (respx), токен не попадает в ответы и логи (как
test_api_key_never_returned_or_logged), пагинация, дубли, ошибки доступа.
