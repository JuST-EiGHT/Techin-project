Шаг 3.6 — выплаты и баланс у Ozon: история выплат, график, прогноз. План — docs/MONEY.md §1–2.

Область «Финансы Ozon»: работает без банков и без планирования — продавцу видно, когда и сколько
Ozon выплатит.

1. Сверить с docs/ozon/seller_api_2026-10.txt (правило 10): `POST /v1/finance/balance` (бета,
   период ≤ 30 дней; total: opening_balance, accrued, payments[], closing_balance; cashflows) и
   `POST /v1/finance/cash-flow-statement/list` (полумесяцы 1–15 и 16–конец). Дописать
   docs/OZON_API.md. Дат выплат в ответе баланса нет — запрос на один день (date_from = date_to):
   выплаты за день = выплата этого дня. Это предположение — проверить на реальном ключе владельца
   и записать результат в OZON_API.md; если однодневный период Ozon не принимает — окно в 7 дней
   и уточнение дня по полумесяцам cash-flow-statement.
2. Миграция `ozon_balance_days` (день, на начало, начислено, выплачено, на конец, разбивка продаж,
   возвратов и услуг, raw_json, synced_at) — снимок; повтор дня без изменений новой записи не
   создаёт (правило 12). Выплаты с датами — производные (дни, где выплачено ≠ 0).
3. Синхронизация `services/sync/ozon_balance.py` через общий runner (`JOBS`, kind="balance"): при
   добавлении ключа — 90 дней (вместе с начислениями), дальше каждые 6 часов — вчера, сегодня и
   пропуски, как у начислений (шаг 1.4). Сверка: сумма дневных выплат = выплаты полумесяца;
   расхождение — предупреждение.
4. `engine/payouts.py` (чистый модуль):
   - `detect_schedule(payouts, weekly_accruals)` — по 8–12 последним неделям: ежедневный (каждый
     рабочий день) / еженедельный (какой день недели) / нерегулярный; лаг — за какую неделю продаж
     выплата (сумма выплаты ≈ начисления недели N недель назад); комиссия гибкого графика — по
     разнице; уверенность;
   - `forecast(schedule, balance, weekly_accruals, today, horizon)` — выплаты на 4–8 недель: дата
     (выходной или праздник → следующий рабочий день; календарь — данные `app/data/work_calendar.json`,
     его же возьмут налоговые сроки в 3.9), сумма, за какую неделю продаж, вид: по графику /
     оценка (недели, которые ещё идут, — по среднему за 4 недели). Прогноз не больше баланса у Ozon
     плюс будущих начислений.
   Тесты на синтетических историях: еженедельный по средам с лагом 3 недели, ежедневный с
   комиссией, праздник, нерегулярный, мало истории.
5. График выплат — настройка с историей (`ozon_payout_settings`, effective_from): «определять
   автоматически» (по умолчанию) | стандартный график Ozon (справочник `app/data/ozon_payouts.json`
   с датой действия: раз в неделю по средам, лаг ≈ 3 недели — сверить с актуальными условиями Ozon) |
   ежедневно | раз в неделю (день) | свой (день, лаг, комиссия %). Не зашивать в код (правило 13).
6. API: GET `/api/v1/ozon/balance` (период, по дням), GET `/api/v1/ozon/payouts` (история, прогноз,
   следующая выплата, определённый график и уверенность), GET/PUT `/api/v1/ozon/payout-settings`,
   POST `/api/v1/sync/balance`; статус — в `/api/v1/sync/status`.
7. Страница `/dashboard/payouts` (Финансы ▾ → «Выплаты Ozon»): «Следующая выплата» — дата, сумма,
   «по графику» или «оценка»; «На балансе у Ozon сейчас»; график по неделям (Recharts): факт —
   сплошные столбики, прогноз — штриховка; таблица выплат (дата, сумма, за какую неделю продаж,
   комиссия, расхождение с прогнозом); блок «График выплат: определили … — изменить». Без ключа
   Ozon — пустое состояние: выплаты есть только в API (в отчётах XLSX их нет). Обе темы, телефон.

Тесты: синхронизация по дням на фейковых ответах (respx), снимки без дублей, определение графика,
прогноз, история настроек, изоляция пользователей.
