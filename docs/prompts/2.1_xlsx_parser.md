Шаг 2.1 — перенос парсера отчётов Ozon из reference/ozon_calculator.html в Python.

Логика и подводные камни описаны в docs/BUSINESS_LOGIC.md §1–3 — прочитай внимательно.
Структура:
- integrations/xlsx/detector.py — ReportDetector: просматривает все листы и первые ~60 строк,
  находит строку заголовков по набору обязательных признаков + бонусных, со стоп-словами;
  выбирает лучшего кандидата. Возвращает тип ('accrual' | 'realization'), лист, индекс строки.
- integrations/xlsx/parsers/accrual.py и realization.py → NormalizedReportData.
- schemas/report.py — NormalizedReportData (report_type, period, period_start, period_end,
  auto_total, revenue_base, cost_sales, by_type, by_article, missing_cost, warnings).
- Себестоимость пока бери из reference/cost_prices.csv через отдельный интерфейс
  (CostProvider), чтобы на шаге 2.3 подменить на БД без правки парсеров.
- Числа: запятая/точка, пробелы, ₽, минусы, пустые ячейки. Нечитаемое число — warning, а не тихий 0.
- Понятные ошибки: «Не удалось определить тип отчёта Ozon…», «В отчёте о реализации не найден
  показатель "Всего выплат от партнёров"…».

Эндпоинт POST /api/v1/reports/parse — принимает файл, возвращает NormalizedReportData
(сохранение в БД — на шаге 2.2).

Тесты на трёх файлах из backend/tests/fixtures/ с эталонными цифрами из BUSINESS_LOGIC.md,
плюс синтетические: таблица не на первом листе, лишние строки сверху, заголовки с переносами
и лишними пробелами, неизвестный артикул, мусорный файл.
