Шаг 8.4b — несколько магазинов у одного аккаунта. Вставлен по запросу владельца 22.10.2026, до 8.4a: «когда один человек
загружает два API-ключа, товары из разных магазинов сливаются в одном месте — каждый пользователь должен переключаться
между магазинами, и их товары и данные не должны пересекаться».

Причина: все данные привязаны к users.id, а синхронизация брала последний использованный ключ — ключи двух кабинетов Ozon
писали в одни таблицы.

1. Магазин — строка users без входа (email и пароль пусты): `owner_id` — аккаунт человека, `store_name`, `ozon_client_id`
   (кабинет). Первый магазин — сам аккаунт: существующие данные и код данных не меняются. Зависимость
   `services/stores.get_current_store` (заголовок X-Store-Id; нет — первый магазин; чужой, отключённый, неверный — 404)
   вместо `get_current_user` во всех эндпоинтах данных. Аккаунт (`get_current_user`): профиль, пароль, Telegram, список
   магазинов; тема — настройка аккаунта, остальные «Основные настройки» — магазина. Войти магазином нельзя.
2. Один магазин — один кабинет Ozon: ключ другого Client-Id в магазин не добавить (409 → «Добавить отдельным магазином»);
   кабинет, уже подключённый в другом магазине аккаунта, — отказ; пустой магазин (нет ключей и товаров) может сменить
   кабинет.
3. API `/stores`: список (название, кабинет, ключи, уведомления без «Ок»), новый магазин с ключом (проверка в Ozon, сразу
   загрузка товаров, остатков, акций, начислений, выплат, отправлений), переименование, отключение и возврат. Магазины не
   удаляются (правило 12): отключённый пропадает из переключателя и не синхронизируется, данные сохраняются.
4. Фоновые задачи — по магазину (свой ключ); отключённый магазин и закрытый аккаунт не синхронизируются. Журнал действий —
   id магазина. Telegram — чат аккаунта: сообщения всех магазинов одним потоком, с названием магазина и ссылкой `?store=`,
   открывающей сайт в нём; /status — по каждому магазину.
5. Уже смешанные данные: миграция переносит ключи второго и следующих кабинетов в новые магазины (ключи не удаляются и не
   расшифровываются) и сбрасывает «день загружен» начислений у такого аккаунта; товары, которых нет в кабинете магазина
   ни в одном статусе, синхронизация переносит в архив (не удаляет); `./scripts/admin.sh resync email` — загрузить все
   магазины аккаунта из Ozon заново за 90 дней.
6. Интерфейс: полоса «Магазин: …» под шапкой (когда магазинов больше одного), страница «Магазины» в меню аккаунта
   (объяснено, что у магазинов своё, а что общее), выбор — cookie `store_id`, прокси Next передаёт X-Store-Id; вход и выход
   сбрасывают выбор.

Тесты: данные магазинов не пересекаются (товары, ключи, настройки), чужой и неверный магазин — 404, правило кабинета,
переименование и отключение, закрытый аккаунт останавливает все магазины, магазин — не аккаунт, журнал по магазину,
Telegram владельца с названием магазина, resync, архив товаров не из кабинета. Миграция на Postgres с данными «два
кабинета у одного аккаунта» — накат, откат, накат. Браузер — обе темы и 390 px.
