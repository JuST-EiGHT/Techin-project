Шаг 3.12 — банки по API с автообновлением и правила разнесения операций. План и сведения о банках —
docs/MONEY.md §6.

Необязательный источник факта для «Планирования», как и выписка файлом (шаг 3.11).

1. integrations/bank/base.py — BankProvider: check_access, list_accounts, transactions(счёт,
   период, курсор), balances. Ошибки банка → понятные русские тексты (как OzonAPIError).
2. Первые провайдеры — банки, где токен выдаёт сам клиент: Т-Банк (T-API, выписка
   bank-statement; лимит 10 запросов/с), Точка (выжимка — docs/banks/TOCHKA.md, спецификация —
   docs/banks/tochka/; разрешения только на чтение; тесты — по примерам спецификации и в
   песочнице), Модульбанк — если API доступен клиенту. Перед реализацией сверить эндпоинты,
   авторизацию и лимиты с официальной документацией банка; если её нельзя открыть из облачной
   среды — попросить владельца выгрузить её в docs/banks/ (как docs/ozon/). Для Точки ещё
   нужны страницы «Авторизация по OAuth 2.0», «Выписки», «Вебхуки», «Лимиты» — их нет в спецификации.
3. bank_connections: провайдер, токен только Fernet-шифротекст (правило 7 — никогда не
   логировать и не возвращать), статус, срок, last_sync_at. Права — только чтение выписок.
4. Синхронизация через общий runner (services/sync/runner.JOBS, kind="bank"): при
   подключении — история насколько отдаёт банк, дальше — каждые 30–60 минут и кнопка
   «Обновить». Дубли с операциями из файла (шаг 3.11) не создавать; операции — в `money_operations`
   (источник bank), поступление от Ozon закрывает выплату Ozon, как в 3.11.
5. API: POST /api/v1/bank/connections (проверить доступ и сохранить), GET, DELETE,
   POST /{id}/verify; статус синхронизации банка — в GET /api/v1/sync/status.
6. /dashboard/settings/banks (пункт «Банки» в меню аккаунта) — подключение банка с пошаговой инструкцией «где взять токен»
   для каждого банка; статус и время последнего обновления.
7. Правила разнесения `categorization_rules`: условия (ИНН или название контрагента, слова в назначении,
   направление, диапазон суммы) → статья; приоритет правил. Встроенные: маркетплейсы по ИНН, переводы
   между своими счетами, налоги по реквизитам казначейства (ЕНП — закрывает плановый налог шага 3.9).
   Ручная разметка важнее правил и не перезаписывается; из ручной разметки — предложение «создать
   правило для всех операций этого контрагента»; пересчёт по новому правилу — только неразмеченных
   вручную. Правила применяются и к операциям из файла (3.11) и импорта (3.8). API: CRUD правил,
   массовая разметка; в «Планировании» → «Операции» — фильтр «без статьи».

Тесты: на фейковых ответах банков (respx), токен не попадает в ответы и логи (как
test_api_key_never_returned_or_logged), пагинация, дубли, ошибки доступа; приоритет правил, ручная
разметка не теряется, переводы между своими счетами.
