Шаг 8.4a — запуск на реальных данных: владелец пользуется сервисом как обычный продавец, проверяем каждую функцию и
исправляем найденное. Делается после карты сервиса (фаза 10, решение владельца 22.10.2026), до лендинга и тарифов;
чек-лист — по разделам новой карты (`docs/SITEMAP.md`). Ошибки, найденные на сервере раньше, исправляются сразу
отдельными сессиями, как исправление начислений 20.10.2026.

До сих пор все интеграции проверялись на фейковых ответах и песочницах — настоящий магазин покажет расхождения.

1. Владелец, как любой пользователь (данные владельца в код не загружаем): подключает ключ Ozon, задаёт налоговый профиль,
   вносит себестоимость по шаблону, загружает прошлые XLSX-отчёты, при желании — включает «Планирование», выписку или
   банк по API, привязывает Telegram. С этого дня копится история цен, остатков и акций (docs/DATA_HISTORY.md).
2. Чек-лист docs/LAUNCH_CHECKLIST.md — по каждому разделу: что проверить, с чем сверить, результат (✅ / ❌ и что
   исправлено):
   - синхронизации Ozon (товары, цены, остатки, начисления, баланс и выплаты, акции, отправления) — без ошибок в журнале,
     объёмы и время, лимиты Ozon;
   - цифры против кабинета Ozon: выручка и начисления за неделю, баланс и выплаты, остатки по складам, акции;
   - P&L по XLSX-отчётам против эталонного калькулятора (reference/ozon_calculator.html) — до копейки;
   - отчёт о реализации, полученный через API (шаг 10.12), против XLSX того же месяца: «Итого реализовано», «Всего
     выплат от партнёров», штуки и суммы по товарам (поля API без описаний — итоги собраны по предположению); документы
     файлом (взаиморасчёты, компенсации) открываются;
   - товары, минимальная цена, склады и поставки, планирование, банк;
   - изменение цены — сначала на одном товаре с предпросмотром, откат; вход и выход из акции — только предпросмотр,
     если владелец не решит иначе;
   - аномалии и уведомления: нет ли ложных тревог на реальных данных, пороги;
   - бэкап и проверка восстановления, мониторинг, письма об ошибках в Sentry.
   - магазины (шаг 8.4b): если ключи двух кабинетов уже были у одного аккаунта — после обновления
     `./scripts/admin.sh resync email`; товары, начисления, остатки каждого магазина — против своего кабинета;
     переключатель, уведомления в Telegram с названием магазина.
3. Каждое расхождение — исправить в коде с тестом на реальном формате ответа (без данных владельца в репозитории — правило
   11: в тесты — обезличенные ответы), обновить docs/OZON_API.md, если API Ozon отвечает не так, как в документации.

Шаг закончен, когда весь чек-лист — ✅ или осознанно отложен владельцем. С даты этого шага идёт отсчёт «нескольких месяцев
без инцидентов» для фазы 9.
