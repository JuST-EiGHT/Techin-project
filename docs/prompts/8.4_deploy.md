Шаг 8.4 — деплой на VPS (Timeweb Cloud или аналог, Ubuntu). Идёт первым в фазе 8 (порядок — docs/ROADMAP.md):
сначала сервис начинает работать для владельца на реальных данных, лендинг, тарифы и оплата — потом.

Сервер покупает и запускает владелец по инструкции — у Claude из облачной среды доступа к серверу нет. Всё остальное
(файлы, скрипты, проверки) делается и проверяется здесь: прод-сборка поднимается локально в Docker с теми же файлами.

1. Прод-сборка: docker-compose.prod.yml (уже есть — довести: без маунтов кода, `next build` / `next start`, uvicorn без
   --reload и с воркерами, celery worker + beat, bot, restart, лимиты памяти, healthcheck), .env.prod.example со всеми
   переменными и пояснениями (ENCRYPTION_KEY, SECRET_KEY, БД, Redis, SITE_URL, Telegram, Sentry, бэкапы), миграции при
   выкладке. Корневой сертификат Минцифры — уже в коде клиента банков (docs/banks/TBANK.md, «TLS»).
2. Безопасность выхода в интернет: регистрация закрыта по умолчанию (REGISTRATION_MODE = closed | invite | open;
   closed — только созданные администратором, invite — по коду приглашения), команды администратора в контейнере
   (создать пользователя, сбросить пароль, выдать приглашение) — почты ещё нет (шаг 8.3a); cookies Secure, CORS —
   только домен сервиса, лимит попыток входа, /docs и /openapi.json закрыты в проде, заголовки безопасности.
3. Nginx с HTTPS (Let's Encrypt, автопродление, редирект 80→443, HSTS, gzip, лимит размера загрузки под отчёты и
   выписки), scripts/setup.sh для первого запуска с нуля и scripts/deploy.sh для обновления (git pull → сборка →
   миграции → перезапуск → проверка /health, при ошибке — откат на прошлую версию).
4. Бэкап Postgres в Object Storage: каждые 6 часов (30 копий) + ежедневные за 30 дней + ежемесячные за 12 месяцев,
   раз в месяц — проверка восстановления в отдельную БД (docs/DATA_HISTORY.md); файлы отчётов и выписок — в БД, входят в
   бэкап. Sentry (бэкенд, воркер, фронт), внешний мониторинг доступности (/health), логи с ротацией.
5. README-DEPLOY.md — пошагово с нуля для человека без опыта: какой сервер выбрать (в РФ — 152-ФЗ), домен и DNS,
   установка, первый пользователь, Telegram-бот у @BotFather (docs/TELEGRAM.md), бэкапы, обновление, что делать, если
   сайт не открывается.

Тесты: режимы регистрации, команды администратора, лимит попыток входа, закрытые /docs в проде; прод-сборка локально —
`docker compose -f docker-compose.prod.yml up` и проверка /health, входа и главных страниц (Playwright).
Дальше — шаг 8.4a: владелец подключает свой магазин, и мы проверяем всё на реальных данных.
