# Режим Operate подробно (и заметки про Read)

Когда дизайн СЛУЖИТ продукту: интерфейс приложения, дашборды, панели настроек, таблицы данных, инструменты, всё за
входом — везде, где пользователь занят задачей. Основное — в SKILL.md («Режимы») и [craft-floor.md](craft-floor.md);
этот файл — углублённый, для поверхностей Operate. Поверхности Read (справка, «Как считаем», длинные тексты) берут режим
Read из SKILL.md плюс правила шрифта и единообразия отсюда; для них длина строки и навигация важнее плотности компонентов.

В нашем сервисе Operate — всё под `/dashboard`. Правила проекта — [project-ru.md](project-ru.md).

## Проверка на «продуктовую халтуру»

Привычность здесь часто — достоинство. Проверка: может ли пользователь, знакомый с такими сервисами (кабинет Ozon,
MPStats, банковские кабинеты), сразу доверять интерфейсу, или он спотыкается на каждом «чуть не таком» элементе.

Провал продуктового интерфейса — не скука, а странность без цели: перегруженные кнопки, разнобой полей ввода, лишнее
движение, акцидентные шрифты вместо подписей, выдуманные элементы для стандартных задач. Планка — заслуженная
привычность. Инструмент должен растворяться в задаче.

## Шрифт

- **Часто достаточно одного семейства.** Продуктовому интерфейсу не нужна пара «заголовочный + основной». Хорошо
  настроенный гротеск несёт заголовки, кнопки, подписи, текст и данные. Шрифт обязан поддерживать кириллицу.
- **Фиксированная шкала в rem, не «резиновая».** Заголовки через clamp продуктовому интерфейсу не нужны.
- **Плотнее шаг шкалы.** Обычно 1,125–1,2 между ступенями. Текстовых элементов здесь больше, чем на бренд-страницах;
  преувеличенный контраст создаёт шум.
- **Длина строки для текста по-прежнему 65–75 знаков.** Данные и компактный интерфейс могут быть плотнее; таблица
  шириной 120+ знаков — нормально.
- **Цифры** в таблицах, карточках и итогах — моноширинные по ширине (`tabular-nums`), выровнены по правому краю.

## Цвет

Продукт по умолчанию сдержан. Отдельная поверхность может заслужить насыщенность (дашборд, где один цвет категории
несёт отчёт), но сдержанность — нижний уровень.

- Богатый словарь состояний: наведение, фокус, нажато, недоступно, выбрано, загрузка, ошибка, предупреждение, успех,
  информация. Стандартизируй их. *У нас:* `accent`, `ok`, `bad`, `warn` и их прозрачности (`bg-accent/15`).
- Акцентный цвет — только для главных действий, текущего выбора и индикаторов состояния, не для украшения.
- Второй нейтральный слой для боковых панелей, панелей инструментов и выдвижных панелей (чуть холоднее или теплее фона
  содержимого).
- Деньги: прибыль, рост, «хорошо» — `ok`; убыток, падение, «плохо» — `bad`. Цвет никогда не единственный носитель
  смысла: рядом знак (▲/▼, «−») или слово.

## Раскладка

- Адаптивность — структурная (сворачивание боковой панели, таблица с прокруткой или карточками, колонки по точкам
  перелома), а не «резиновый» шрифт. У нас: полное меню — с 1280 px, телефон — 390 px.

## Компоненты

У каждого интерактивного компонента есть состояния: обычное, наведение, фокус, нажато, недоступно, загрузка, ошибка.
Не выпускай с половиной из них.

- Скелетоны при загрузке, а не крутилка посреди содержимого.
- Пустые состояния, которые учат интерфейсу, а не «здесь ничего нет». У нас ещё различаем: «нет данных» ≠ 0
  (правило 12) — пустое состояние говорит, каких данных нет и откуда их взять.
- Одинаковые элементы по всей поверхности. Та же форма кнопки. Тот же словарь полей ввода. Тот же стиль значков.
- Выпадающие окна выходят за контейнер. Абсолютно позиционированный список внутри предка с `overflow: hidden` или
  `overflow: auto` обрежется; используй `<dialog>`, popover API, `position: fixed` или портал (у нас — `Modal` из
  `components/planning/ui.tsx`, панель `FilterButton`).

## Движение

- 150–250 мс на большинство переходов. Пользователь в потоке работы — не заставляй ждать хореографию.
- Движение передаёт состояние, а не украшает. Смена состояния, отклик, загрузка, раскрытие — и ничего больше.
- Никаких постановочных появлений при загрузке страницы. Продукт открывается в задачу; смотреть, как он грузится,
  никто не хочет.
- Уважай `prefers-reduced-motion`.

## Ограничения продукта

- Декоративное движение, не передающее состояние.
- Разный словарь компонентов на разных экранах. Если кнопка «Сохранить» в двух местах выглядит по-разному, одна из них
  неправильная.
- Акцидентные шрифты в подписях, кнопках, данных.
- Переизобретение стандартных элементов ради «характера» (нестандартные поля, странные модальные окна).
- Тяжёлый цвет или полная насыщенность акцента у неактивных состояний.
- Модальное окно как первая мысль. Чаще всего это лень. Сначала исчерпай встроенные и пошаговые варианты.

## Что продукту можно

Продукту можно то, чего нельзя бренд-страницам.

- Системные шрифты и привычные гротески по умолчанию.
- Стандартные схемы навигации: шапка + боковое меню, хлебные крошки, вкладки, командная палитра.
- Плотность. Таблицы с множеством строк, панели с множеством подписей, плотная информация, когда она нужна.
- Единообразие важнее сюрприза. Один и тот же визуальный словарь от экрана к экрану — достоинство; «вау» оставляем
  для моментов, а не для страниц.
