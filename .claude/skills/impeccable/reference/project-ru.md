# Правила проекта для дизайн-скиллов

Сервис аналитики и автоматизации для продавцов Ozon (аналог MPStats, подписка). Пользователь — продавец: смотрит деньги,
товары, остатки, цены, решает, что поднять, что поставить, что вывезти. Работает за компьютером, часто вечером, иногда —
с телефона по уведомлению в Telegram. Этот файл читают и `impeccable`, и `ui-ux-pro-max` перед любой правкой интерфейса.

## Что главнее чего

1. Прямая просьба владельца в текущей сессии.
2. `CLAUDE.md` (правила 1–18) и `docs/SITEMAP.md` — карта сервиса.
3. Этот файл.
4. Правила скиллов (`craft-floor.md`, `operate.md`, база ui-ux-pro-max).

Результаты поиска ui-ux-pro-max и советы impeccable — рекомендации. Они не отменяют правила проекта, не меняют палитру,
не убирают функции и не переименовывают разделы без просьбы владельца.

## Визуальный мир — уже принят

- **Цвета — только токены темы** (`tailwind.config.ts` → `src/app/globals.css`): `bg`, `card`, `line`, `fg`, `muted`,
  `faint`, `accent`, `ok`, `bad`, `warn`, с прозрачностью — `bg-accent/15`. Без hex, без `slate-*`, `gray-*`, `zinc-*`.
  Белый текст на цветной кнопке допустим. Новый цвет — только новым токеном в обеих темах, по просьбе владельца.
- **Две темы:** тёмная по умолчанию (фон #0f1117, карточки #1a1d27, рамки #2a2d3a, акцент #4f8ef7), светлая (фон
  #f6f7fb, карточки #ffffff, рамки #e3e6ee, акцент #2563eb). Переключаются в «Основных настройках» (`data-theme`
  на `<html>`). Каждую правку проверяй в обеих.
- **Шрифт:** сейчас системный гротеск (шрифт не подключён). Смена шрифта — отдельное решение владельца; новый шрифт
  обязан содержать кириллицу (в Google Fonts — `subsets: ['latin', 'cyrillic']`, через `next/font`).
- **Значки:** без эмодзи. Стрелки ▲/▼ и «→» в ссылках «Подробнее →» уже приняты как типографские знаки.

## Общие компоненты — использовать, не дублировать

| Что | Где |
|---|---|
| Меню разделов | `src/lib/nav.ts` (порядок — по `docs/SITEMAP.md`); старые адреса — `src/lib/redirects.ts` |

| Графики: подсказка у курсора, клик → подробности, «Подробнее →» | `components/charts.tsx` — `useDrill`, `TipBox`, `MoreLink`; линии `type="monotone"` (правило 16) |
| Модальные окна, поля ввода | `components/planning/ui.tsx` — `Modal` (портал, окна поверх окон), `input` |
| Время обновления данных, синхронизация | `components/sync.tsx`, `lib/sync.ts` (`UpdatedAt`) |

Если улучшение касается общего компонента — правь его, а не делай локальную копию: так изменение придёт на все страницы.

## Данные на экране

- **Нет данных ≠ 0** (правило 12). «—» или пустое состояние с причиной, а не «0 ₽».
- **Числа:** `Intl.NumberFormat('ru-RU')` — разделитель тысяч — неразрывный пробел, дробная часть через запятую:
  `1 234 567,89 ₽`. В таблицах — `tabular-nums`, по правому краю. Знак минуса — «−» или через форматтер, не дефис.
- **Сравнение с прошлым периодом:** ▲/▼ + цвет `ok`/`bad` + «было …». Цвет не единственный носитель смысла.
- **Деньги под риском, убыток, «ниже минимальной цены»** — `bad`; «внимание», «скоро» — `warn`.
- **Даты:** как в `components/filters.tsx` — `dayLabel` («05.11.2026», коротко «05.11») и `rangeLabel`
  («01.11 – 11.11.2026»); подписи осей графиков могут быть короче. Время — по Москве, если не сказано иное.
- **Форматирование чисел** — уже есть в `lib/analytics.ts` (₽, %, шт., минус «−»); новые форматтеры не заводить.

## Русская типографика

- Кавычки — «ёлочки», внутри — „лапки“.
- Тире — длинное «—» с пробелами вокруг (перед ним — неразрывный пробел); в диапазонах чисел — короткое «–» без
  пробелов: «5–10 дней»; в диапазонах дат — как в `rangeLabel` (с пробелами). Запрет на тире из англоязычных правил против «ИИ-стиля» к русскому не относится.
- Неразрывный пробел: между числом и единицей (`100 ₽`, `5 шт.`, `30 дней`), после коротких предлогов и союзов в
  заголовках («в акции», «на складе»), в «т. е.», «и т. д.».
- Заглавная — только первая буква заголовка и кнопки («Обновить всё», не «Обновить Всё»). Без КАПСА, кроме бейджа
  «СРОЧНО», уже принятого в акциях.
- Русский текст на 15–30 % длиннее английского, слова длиннее: проверяй переносы и обрезку на 390 px; у длинных
  заголовков — `text-wrap: balance`, у длинных слов в узких ячейках — `hyphens: auto` (работает, потому что
  `<html lang="ru">`), у названий товаров — обрезка с полным названием в `title` и подсказке.
- Склонение чисел — `Intl.PluralRules('ru')`: «1 товар», «3 товара», «5 товаров».

## Поведение, которое уже решено

- Изменения в Ozon — только «предпросмотр → подтверждение → журнал» (правило 6); дизайн это не упрощает.
- У каждого вопроса пользователю — зачем мы спрашиваем (правило 15).
- Старые функции при перестройке не удаляются: переезжают или дорабатываются (правило 9).
- Новая страница — в меню на своё место по карте сервиса.
- Фильтры: снаружи только поиск и период, остальное — за «Фильтрами» (правило 18).

## Как проверять

- Тесты фронта и бэка — по правилам `CLAUDE.md` («Как проверять шаг»).
- Браузер: один сценарий Playwright — обе темы и ширина 390 px за один запуск; снимки — только изменённых экранов.
- Детектор impeccable — один раз в конце работы над экраном:
  `.claude/skills/impeccable/scripts/impeccable detect --json <изменённые файлы>`.

## Поправки к поведению скилла в этой среде

- Лаунчер может напечатать `SUBAGENT_AUTHORIZATION` — разрешение запускать субагентов. В этом проекте субагентов
  запускаем только по прямой просьбе пользователя; иначе всё — в основном потоке.
- Хук детектора (`/impeccable hooks on`) не включаем без просьбы: он пишет в `.claude/settings*.json` и запускается
  после каждой правки.
- PRODUCT.md и DESIGN.md создаются командами `init` и `document` только по просьбе владельца; до этого контекст —
  `docs/PROJECT.md`, `docs/SITEMAP.md` и этот файл.
- Вопросы пользователю и отчёты — на русском.
