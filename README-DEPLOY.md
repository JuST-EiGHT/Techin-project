# Как запустить Ozon Analytics на своём сервере

Пошаговая инструкция для человека без опыта администрирования. Займёт 1–2 часа, из них большую часть — ожидание
(DNS, сборка). Все команды копируются как есть; где нужно вписать своё — это отмечено: `ваш-домен`, `you@mail.ru`.

После запуска сайт работает по адресу `https://ваш-домен`, регистрация закрыта для всех, кроме вас и тех, кому вы
выдадите приглашение. Каждые 6 часов делается резервная копия базы, сертификат HTTPS продлевается сам, обновление —
одной командой с автоматическим откатом, если что-то пошло не так.

## 0. Что понадобится и сколько стоит

| Что | Зачем | Примерная цена (октябрь 2026) |
|---|---|---|
| Облачный сервер (VPS) в России: 2 ядра, 4 ГБ памяти, 40–60 ГБ NVMe, Ubuntu 24.04 | на нём работает сервис | 1 000–1 800 ₽ в месяц |
| Домен (например, `myshop-analytics.ru`) или поддомен своего домена (`app.myshop.ru`) | адрес сайта и сертификат HTTPS | .ru — 200–900 ₽ в год; поддомен своего — бесплатно |
| Объектное хранилище S3 у того же провайдера | резервные копии вне сервера | десятки рублей в месяц (копии занимают сотни мегабайт — единицы гигабайт; ~1,5–2,5 ₽ за ГБ в месяц) |
| Sentry (sentry.io, тариф Developer) или GlitchTip | письма об ошибках | бесплатно |
| UptimeRobot (или аналог) | письмо или сообщение в Telegram, если сайт перестал открываться | бесплатно |
| Сертификат HTTPS (Let's Encrypt), Telegram-бот | | бесплатно |

**Итого: примерно 1 100–2 000 ₽ в месяц плюс домен.** Цены у провайдеров меняются — сверяйтесь с их сайтами.

**Почему сервер в России.** По 152-ФЗ (ст. 18, ч. 5) персональные данные граждан РФ — email и имена пользователей
сервиса — должны записываться и храниться в базах данных на территории России. Поэтому сервер и хранилище копий — у
российского провайдера: Timeweb Cloud, Selectel, Yandex Cloud, REG.RU Cloud и др. Ниже примеры для **Timeweb Cloud** —
у него простая панель и хранилище S3 там же; у других провайдеров шаги такие же, названия пунктов немного другие.
Ошибки, которые уходят в Sentry, персональных данных не содержат (сервис их вырезает). Когда сервис откроется другим
продавцам (шаги 8.3 и дальше), понадобятся политика обработки персональных данных и уведомление Роскомнадзора — это
будет в шаге лендинга.

**Что выбрать в конфигурации и почему так.** 4 ГБ памяти — с запасом на сборку сайта (самый требовательный момент) и
на фоновые синхронизации с Ozon; на 2 ГБ сборка может не пройти. Диск NVMe 40–60 ГБ: база одного магазина растёт на
сотни мегабайт в год, остальное — образы Docker и 4 последние копии. Ubuntu 24.04 LTS — с ней проверены скрипты
(22.04 тоже подойдёт).

## 1. Сервер

1. Зарегистрируйтесь на [timeweb.cloud](https://timeweb.cloud) и пополните баланс.
2. **SSH-ключ** — вход на сервер без пароля, его нельзя подобрать. На своём компьютере откройте терминал
   (Windows — «PowerShell», macOS — «Терминал») и выполните:
   ```
   ssh-keygen -t ed25519
   ```
   На все вопросы — Enter. Затем покажите публичную часть ключа и скопируйте строку целиком (начинается с `ssh-ed25519`):
   ```
   cat ~/.ssh/id_ed25519.pub
   ```
   (в Windows: `type $env:USERPROFILE\.ssh\id_ed25519.pub`)
3. В панели: **Облачные серверы → Создать**:
   - образ — **Ubuntu 24.04**;
   - регион — Москва или Санкт-Петербург;
   - конфигурация — **2 × CPU, 4 ГБ RAM, 50 ГБ NVMe** (ближайшая к этому);
   - SSH-ключ — **Добавить** и вставить скопированную строку;
   - публичный IPv4 — нужен (обычно включён).
4. Через минуту-две сервер запустится. Запишите его **IP-адрес** (вида `185.12.34.56`).
5. Подключитесь со своего компьютера:
   ```
   ssh root@185.12.34.56
   ```
   На вопрос «Are you sure you want to continue connecting» — `yes`. Вы на сервере: строка начинается с `root@…`.
   Все команды дальше выполняются здесь, на сервере.

## 2. Домен и DNS

1. Купите домен у любого регистратора (REG.RU, RU-CENTER, Timeweb…) или используйте поддомен уже своего домена —
   например, `app.myshop.ru`.
2. В настройках DNS домена (у регистратора или в панели Timeweb → «Домены») добавьте **A-запись**:
   - для поддомена: имя `app` (или любое другое), значение — IP сервера;
   - для всего домена: имя `@`, значение — IP сервера.
3. Подождите 15–60 минут. Проверить, что запись заработала, — на своём компьютере:
   ```
   ping app.myshop.ru
   ```
   В ответе должен быть IP вашего сервера. Можно и на сайте [dnschecker.org](https://dnschecker.org).

Пока домен не указывает на сервер, сертификат HTTPS не выпустится — установка остановится и подскажет, что не так.

## 3. Скачать проект на сервер

Если репозиторий закрытый, серверу нужен свой ключ доступа «только чтение» (deploy key). На сервере:

```
ssh-keygen -t ed25519 -f ~/.ssh/github_deploy -N "" -C "ozon-analytics-server"
cat ~/.ssh/github_deploy.pub
```

Скопируйте строку, откройте на GitHub репозиторий → **Settings → Deploy keys → Add deploy key**: название —
«Сервер», ключ — вставить, галочку «Allow write access» **не** ставить → **Add key**. Затем на сервере:

```
printf 'Host github.com\n  IdentityFile ~/.ssh/github_deploy\n' >> ~/.ssh/config
apt-get update && apt-get install -y git
git clone git@github.com:JuST-EiGHT/Techin-project.git /opt/ozon-analytics
cd /opt/ozon-analytics
```

(Если репозиторий открытый — ключ не нужен: `git clone https://github.com/JuST-EiGHT/Techin-project.git /opt/ozon-analytics`.)

## 4. Установка

```
cd /opt/ozon-analytics
sudo ./scripts/setup.sh
```

Скрипт спросит домен (`app.myshop.ru`, без `https://`) и почту (на неё Let's Encrypt пишет, если с сертификатом что-то
не так). Дальше всё сам, 10–20 минут:

- ставит Docker, включает файрвол (открыты только SSH, 80 и 443), защиту SSH от подбора пароля (fail2ban),
  автообновления безопасности Ubuntu, файл подкачки;
- создаёт `.env.prod` — настройки сервера — и сам генерирует секреты: ключ входа, ключ шифрования ключей Ozon и
  токенов банков, пароль базы;
- проверяет, что домен указывает на этот сервер, и выпускает сертификат Let's Encrypt;
- собирает сервис, создаёт таблицы базы, запускает всё и проверяет, что сайт отвечает.

В конце — «Сервер готов: https://ваш-домен». Запуск повторять безопасно: что уже сделано, пропускается.

**Сохраните настройки.** Покажите файл и скопируйте его целиком в менеджер паролей (или в надёжную заметку):

```
cat /opt/ozon-analytics/.env.prod
```

Главное в нём — `ENCRYPTION_KEY`: им зашифрованы ключи Ozon и токены банков. Если сервер пропадёт, базу можно
восстановить из копии, но без этого ключа сохранённые ключи Ozon придётся ввести заново.

## 5. Первый пользователь — вы

Почты в сервисе пока нет (будет в шаге 8.3a), поэтому пользователей и пароли выдаёт администратор — вы — командами на
сервере. Все команды — из папки `/opt/ozon-analytics`.

```
cd /opt/ozon-analytics
./scripts/admin.sh create-user you@mail.ru --name "Ваше имя"
```

Команда покажет пароль один раз. Откройте `https://ваш-домен`, войдите, затем смените пароль: меню аккаунта (справа
вверху) → «Профиль и безопасность» → «Сменить пароль». Хотите сразу свой пароль — добавьте `--ask`, команда спросит его.

Дальше — шаг 8.4a: подключите ключ Ozon, налоговый профиль, себестоимость, загрузите прошлые отчёты. С этого дня сервис
начинает копить историю цен, остатков и акций.

### Кто может зарегистрироваться

В `.env.prod` — строка `REGISTRATION_MODE`:

| Значение | Что это значит |
|---|---|
| `invite` (так по умолчанию) | Регистрация только по приглашению. Без кода на странице регистрации — отказ. |
| `closed` | Регистрации нет вовсе: аккаунты создаёте вы командой `create-user`. |
| `open` | Любой может зарегистрироваться. Включать после шага 8.3a (подтверждение почты). |

Поменять: `nano .env.prod` → исправить строку → `Ctrl+O`, `Enter` (сохранить), `Ctrl+X` (выйти) →
`./scripts/compose.sh up -d` (подхватить изменения).

### Команды администратора

| Команда | Что делает |
|---|---|
| `./scripts/admin.sh invite --email friend@mail.ru --note "Иван"` | Приглашение: код и ссылка `https://ваш-домен/register?invite=…`. Действует 7 дней, один раз. `--email` — только для этого адреса (можно без него), `--days 14` — другой срок. Код показывается один раз. |
| `./scripts/admin.sh invites` | Действующие приглашения (`--all` — все, с тем, кто зарегистрировался). |
| `./scripts/admin.sh revoke-invite e26507fc` | Отозвать приглашение (id — первые 8 знаков из списка, или сам код). |
| `./scripts/admin.sh create-user email --name "Имя"` | Создать пользователя (пароль — случайный или `--ask`). |
| `./scripts/admin.sh reset-password email` | Забыли пароль: новый пароль, выход на всех устройствах, снимает блокировку входа. |
| `./scripts/admin.sh users` | Список пользователей. |
| `./scripts/admin.sh deactivate email` / `activate email` | Закрыть / вернуть доступ. Данные пользователя остаются. |
| `./scripts/admin.sh unblock email` | Снять блокировку входа после 5 неверных паролей (иначе снимается сама через 15 минут). |
| `./scripts/admin.sh resync email` | Загрузить заново из Ozon данные всех магазинов аккаунта: товары, остатки, акции, отправления, начисления и баланс за 90 дней. Отчёты XLSX, себестоимость и планирование не трогает. |

**Если у аккаунта были ключи двух разных кабинетов Ozon** (до обновления с магазинами, шаг 8.4b): обновление само
разделит их — второй кабинет станет отдельным магазином (меню аккаунта → «Интеграции» → «Ozon», переключатель — под шапкой сайта).
Чтобы убрать из первого магазина то, что успело попасть туда из второго кабинета, после обновления выполните один раз
`./scripts/admin.sh resync ваш@email`: товары чужого кабинета уйдут в архив, начисления и баланс перезагрузятся ключом
своего магазина (это копии данных Ozon — ничего из того, что вы вносили сами, не удаляется).

Действия с пользователями записываются в журнал действий (`audit_log`) — он не меняется и не удаляется.

## 6. Telegram-бот

Уведомления об аномалиях в Telegram (подробно — `docs/TELEGRAM.md`). Бот один на весь сервис, каждый пользователь
подключает к нему свой чат с сайта.

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → название («Ozon Analytics») → имя бота,
   оканчивающееся на `bot` (например, `myshop_analytics_bot`). BotFather пришлёт токен вида `123456789:AA…`.
2. На сервере: `nano /opt/ozon-analytics/.env.prod` и впишите:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AA…
   TELEGRAM_BOT_USERNAME=myshop_analytics_bot
   ```
   (имя — без `@`). Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.
3. Применить: `./scripts/compose.sh up -d`
4. На сайте: меню аккаунта → «Интеграции» → «Telegram» → «Подключить Telegram» → «Открыть бота» → в Telegram — «Запустить».

Токен никому не показывайте и в репозиторий не добавляйте: с ним можно писать от имени бота.

## 7. Резервные копии

Работают сразу после установки, без настройки:

- **каждые 6 часов** (03:15, 09:15, 15:15, 21:15 по Москве) — копия базы: все данные, включая загруженные отчёты и
  выписки; на сервере хранятся 4 последние;
- **перед каждым обновлением** — копия «на всякий случай» (5 последних);
- **1-го числа каждого месяца** — проверка: последняя копия разворачивается в отдельную базу и сверяется с рабочей.

Но копии только на сервере пропадут вместе с ним — нужно хранилище вне сервера. С ним копии хранятся так: каждые
6 часов — 30 последних (неделя), ежедневные — 30 дней, ежемесячные — 12 месяцев.

### Подключить хранилище (Timeweb Cloud)

1. Панель → **Хранилище S3 → Создать**: тип — **приватное**, имя — например `myshop-backups`.
2. В карточке хранилища найдите **адрес (endpoint)**, **регион**, **Access Key** и **Secret Key**.
3. На сервере `nano /opt/ozon-analytics/.env.prod` и впишите:
   ```
   BACKUP_S3_ENDPOINT=https://s3.timeweb.cloud
   BACKUP_S3_REGION=ru-1
   BACKUP_S3_BUCKET=myshop-backups
   BACKUP_S3_ACCESS_KEY=…
   BACKUP_S3_SECRET_KEY=…
   ```
   (адрес и регион — как в карточке хранилища; у Yandex Object Storage — `https://storage.yandexcloud.net` и
   `ru-central1`, у Selectel — `https://s3.ru-1.storage.selcloud.ru` и `ru-1`).
4. Применить и сразу проверить:
   ```
   ./scripts/compose.sh up -d
   ./scripts/compose.sh exec backup backup.sh
   ```
   В конце должно быть «резервная копия готова», а в хранилище появятся папки `6h`, `daily`, `monthly`.
5. Проверить восстановление (не трогает рабочую базу):
   ```
   ./scripts/compose.sh exec backup restore-check.sh
   ```
   В конце — «проверка восстановления пройдена».

### Восстановить базу из копии

```
./scripts/restore.sh                                    # список копий
./scripts/restore.sh daily/ozon_2026-10-18_001500.dump  # восстановить выбранную
```

Скрипт попросит написать «ВОССТАНОВИТЬ», сначала сохранит текущую базу (`predeploy_…` — так что шаг можно отменить
тем же скриптом), остановит сервисы, восстановит копию и запустит всё снова. Всё, что появилось после копии, пропадёт:
начисления Ozon догрузятся синхронизацией, а снимки цен и остатков за этот промежуток — нет.

### Переезд на новый сервер или сервер пропал

Новый сервер → шаги 1–3 → положите сохранённый `.env.prod` в `/opt/ozon-analytics/` (поправьте `DOMAIN`, если домен
другой) → `sudo ./scripts/setup.sh` → `./scripts/restore.sh` и выберите последнюю копию из хранилища.

## 8. Мониторинг и ошибки

### Ошибки — в Sentry

1. Зарегистрируйтесь на [sentry.io](https://sentry.io) (тариф Developer — бесплатный) или используйте GlitchTip
   (совместим с Sentry, есть бесплатный тариф и вариант на своём сервере).
2. Создайте проект (платформа — Python / FastAPI), скопируйте **DSN** (Settings → Client Keys) — строку вида
   `https://abc123@o123.ingest.sentry.io/456`.
3. В `.env.prod`: `SENTRY_DSN=https://…` и пересоберите сервис (адрес Sentry вписывается в код сайта при сборке):
   ```
   ./scripts/deploy.sh --force
   ```

Ошибки сервера, фоновых задач, бота, сайта в браузере и сбои резервных копий придут письмом. Пароли, ключи Ozon, тела
запросов, IP и email пользователей в Sentry не отправляются; токен бота вырезается.

### Сайт недоступен — сообщение вам

1. Зарегистрируйтесь на [uptimerobot.com](https://uptimerobot.com) (бесплатно).
2. **Add New Monitor**: тип — HTTP(s), адрес — `https://ваш-домен/health`, интервал — 5 минут.
3. Оповещения — почта или Telegram (в UptimeRobot: My Settings → Alert Contacts).

`/health` отвечает «ok», только если работают и сайт, и база, и Redis. Можно проверить и самому:
`curl https://ваш-домен/health` → `{"status":"ok","version":"…","db":"ok","redis":"ok"}`.

### Копии перестали делаться — сообщение вам (по желанию)

На [healthchecks.io](https://healthchecks.io) (бесплатно) создайте проверку с периодом 6 часов и запасом 1 час,
скопируйте её адрес в `BACKUP_HEARTBEAT_URL=` в `.env.prod`, затем `./scripts/compose.sh up -d`. Если очередная копия
не отметится вовремя, придёт письмо.

### Журналы

```
./scripts/compose.sh logs --tail 100 api        # сервер API (Ctrl+C — выйти, если с -f)
./scripts/compose.sh logs -f worker             # фоновые синхронизации с Ozon
./scripts/compose.sh logs --tail 50 backup      # резервные копии
```

Журналы хранятся с ротацией: до 50 МБ на сервис, старое удаляется само.

## 9. Обновление

Когда в репозитории появились изменения (новый шаг готов и слит в main):

```
cd /opt/ozon-analytics
./scripts/deploy.sh
```

Что происходит: скачивается обновление → собирается новая версия (сайт в это время работает на старой) → копия базы →
изменения структуры базы (миграции) → перезапуск → проверка, что сайт отвечает. Если новая версия не поднялась за
3 минуты — **откат сам**: миграции назад, прежняя версия, прежний код; в конце — «вернул прежнюю …, сайт работает»
и журнал ошибки. Если сборка или миграции не прошли — сайт и не останавливался.

`./scripts/deploy.sh --force` — пересобрать и перезапустить без изменений в коде (например, после смены `SENTRY_DSN`).
Какая версия работает — `cat .deploy/version` или `curl https://ваш-домен/health`.

Изменили только `.env.prod` (Telegram, хранилище, режим регистрации) — достаточно `./scripts/compose.sh up -d`.

## 10. Если сайт не открывается

Идите по порядку — большинство проблем решается на первых пунктах.

1. **Что запущено:**
   ```
   cd /opt/ozon-analytics
   ./scripts/compose.sh ps
   ```
   У всех сервисов должно быть `Up` (у `api`, `worker`, `frontend`, `db`, `redis` — ещё `(healthy)`). Сервис `bot`
   без токена Telegram — `Exited (0)`, это нормально.
2. **Что говорит сам сервис:** `curl -s https://ваш-домен/health`
   - `"db":"error"` — база: `./scripts/compose.sh logs --tail 50 db`;
   - `"redis":"error"` — `./scripts/compose.sh restart redis`;
   - ответа нет совсем — пункт 4 (Nginx) или 6 (сертификат).
3. **Перезапустить всё:** `./scripts/compose.sh up -d` — поднимет упавшее. Один сервис: `./scripts/compose.sh restart api`.
4. **«502 Bad Gateway»** — Nginx работает, а API или сайт нет: `./scripts/compose.sh logs --tail 100 api frontend` —
   в конце будет причина.
5. **Сервер перезагрузили** — всё поднимается само через минуту-две. Если нет — `./scripts/compose.sh up -d`.
6. **Браузер пишет «Подключение не защищено»** — сертификат: `./scripts/compose.sh logs --tail 30 certbot`.
   Продлить вручную:
   ```
   ./scripts/compose.sh run --rm --entrypoint certbot certbot renew --webroot -w /var/www/certbot
   ./scripts/compose.sh restart nginx
   ```
   Если меняли домен или IP — проверьте A-запись (раздел 2).
7. **Место на диске:** `df -h /` — если занято больше 90 %:
   ```
   docker system prune -f        # удаляет только остановленные контейнеры и неиспользуемые слои образов
   ```
   Никогда не запускайте `docker system prune --volumes` и `docker volume rm` — это удалит базу.
8. **Память:** `free -h` и `docker stats --no-stream` — какой сервис занимает больше всего.
9. **Не можете войти — «Слишком много неудачных попыток»:** подождите 15 минут или `./scripts/admin.sh unblock email`.
   Забыли пароль — `./scripts/admin.sh reset-password email`.
10. **После обновления что-то сломалось**, а автоматический откат не сработал: пришлите в Claude Code вывод
    `./scripts/compose.sh ps` и `./scripts/compose.sh logs --tail 200 api` (проверьте, что в нём нет паролей и токенов).
    База в безопасности: перед обновлением сделана копия (`./scripts/restore.sh` покажет `predeploy_…`).

## 11. Что где лежит и как защищено

| Что | Где |
|---|---|
| Проект | `/opt/ozon-analytics` |
| Настройки и секреты | `/opt/ozon-analytics/.env.prod` (доступ только у root, в репозиторий не попадает) |
| Какая версия работает | `.deploy/version` (прошлая — `.deploy/previous`) |
| База, Redis, сертификаты, копии на сервере | тома Docker `ozon-analytics_postgres_data`, `_redis_data`, `_letsencrypt`, `_backups` |
| Сборка и сервисы | `docker-compose.prod.yml`; Nginx — `docker/nginx/`; копии — `docker/backup/`; скрипты — `scripts/` |

| Сервис | Что делает |
|---|---|
| `nginx` | Единственный, кто открыт в интернет (порты 80 и 443): HTTPS, перенаправление с http, сжатие, заголовки безопасности |
| `frontend` | Сайт (Next.js); к API ходит сам, браузер API напрямую не видит |
| `api` | Сервер API (FastAPI, 2 процесса) |
| `worker`, `beat` | Фоновые задачи: синхронизации с Ozon и банками, аномалии, уведомления, удаление аккаунтов через 30 дней после запроса (ночью, 03:13 МСК) — и их расписание |
| `bot` | Telegram-бот (без токена не запускается) |
| `db`, `redis` | База PostgreSQL 16 и Redis — только внутри сервера |
| `backup` | Резервные копии и проверка восстановления |
| `certbot` | Продление сертификата Let's Encrypt (проверка дважды в сутки) |

Защита:

- регистрация закрыта (`invite` / `closed`), пароли — только хэши, коды приглашений — только хэши;
- лимит неудачных входов: 5 попыток на email с одного адреса и 20 на любые email за 15 минут, плюс 10 запросов входа в
  минуту с адреса на уровне Nginx; неверные коды приглашений — 10 в час;
- cookies входа — `HttpOnly`, `Secure`, `SameSite=Lax`; токены в JavaScript браузера не попадают;
- HTTPS с HSTS, заголовки безопасности (запрет встраивания сайта в чужие страницы, CSP и др.), версия Nginx скрыта;
- документация API (`/docs`, `/openapi.json`) на сервере закрыта; API наружу не открыт — только через сайт;
- с ключом по умолчанию или адресом без https API не стартует;
- ключи Ozon и токены банков — зашифрованы (`ENCRYPTION_KEY`), в журналы и ответы не попадают;
- файрвол (только SSH, 80, 443), fail2ban для SSH, автообновления безопасности Ubuntu;
- журнал действий (`audit_log`) не меняется и не удаляется — это проверяет сама база;
- сертификат Минцифры для банков (Т-Банк, Точка) уже в коде — на сервере ничего ставить не нужно.
